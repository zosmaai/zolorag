# zoloRAG — Zosma AI Local RAG. Plan.

**zoloRAG** = **Zo**sma **A**I **L**ocal **RAG** — a fully local, offline, desktop app for chatting with your PDFs, powered by a local AI model on your own machine.

---

## Problem Statement

### The AI Divide

Artificial intelligence is reshaping how we interact with information, but accessing it still requires:

- **💰 Monthly subscriptions** to ChatGPT Plus, Claude Pro, or GitHub Copilot ($10–$30/mo).
- **🔗 Internet dependency** — cloud AI is unusable without a stable connection.
- **📤 Privacy concerns** — sensitive documents (legal, medical, financial) must be uploaded to third-party servers.
- **🧑‍💻 Technical know-how** — local AI solutions demand Python, terminals, and manual setup.

### Who Gets Left Out

| User Profile | Why They Can't Use Cloud AI | Why They Can't Use Existing Local Tools |
|-------------|---------------------------|----------------------------------------|
| **Office worker** with company PDFs | IT policy blocks uploading to cloud | Can't run Python scripts |
| **Student** on a budget | Can't afford $20/mo subscriptions | Has only a laptop, no dev environment |
| **Small business owner** | Has contracts, manuals, reports in PDFs | Needs privacy, but also simplicity |
| **Retired / non-tech person** | Has questions about their medical or legal PDFs | "Just want to drag a file and talk to it" |
| **Government / healthcare worker** | Strict compliance (HIPAA, GDPR) forbids cloud sharing | Existing tools are developer-only |

### The Core Problem

> **There is no easy way for a non-technical person to open a PDF on their own computer and ask natural-language questions about it — entirely offline, privately, and with zero subscriptions.**

Existing solutions are either:
- **Cloud-only** (ChatGPT, Claude, Gemini) — require internet, subscription, and trust.
- **Developer-focused** (LangChain CLI, privateGPT, local RAG scripts) — require Python, terminal, and configuration.
- **Half-baked** — browser extensions that don't run models locally, or limited mobile apps.

---

## Solution: zoloRAG

A **desktop GUI application** that lets anyone:

1. **Drag & drop** one or more PDFs.
2. **Click "Index"** — the app parses, chunks, and indexes them locally.
3. **Type questions** — get answers grounded in the PDF content, generated by a local AI model.
4. **Stay offline** — everything runs on-device. No accounts, no cloud, no subscriptions.

### Design Principles

| Principle | Why |
|-----------|-----|
| **Zero configuration** | Install once, open, use. No Python, no terminal, no API keys. |
| **Privacy by default** | All data stays on-device. No telemetry. No uploads. |
| **Offline-first** | Works without internet after initial model download. |
| **Free & open source** | No paywalls, no tiers, no "pro" features locked away. |
| **Cross-platform** | Windows, macOS, and Linux with a native feel. |
| **Progressive disclosure** | Simple defaults for beginners, advanced settings for power users. |

### Component Breakdown

#### 1. PDF Ingestion Pipeline

| Sub-component | Rust Crate | Role |
|--------------|-----------|------|
| **PDF Parser** | `lopdf` or `pdf-extract` | Extract text from PDF pages. Handles text-based PDFs. |
| **OCR Engine** | Shell to Tesseract or `leptess` | Fallback for scanned/image-only PDFs. User opt-in. |
| **Chunker** | Custom Rust | Split extracted text into chunks (~200–500 tokens). |

#### 2. Semantic Index

| Sub-component | Rust Crate | Role |
|--------------|-----------|------|
| **Embedding Model** | `fastembed` or `candle` + ONNX | Convert text chunks to dense 384-dim vectors. Same model as Python's sentence-transformers. |
| **Binarizer** | `vec.iter().map(\|f\| *f > 0.0)` | Convert floats to bits (1/0). 50× faster matching, 32× smaller memory. |
| **Index** | Custom Rust (40 lines) | Hamming distance over `Vec<u64>` with SIMD. Fast nearest-neighbor search. |
| **Persistence** | `serde` + `bincode` | Save/load index between sessions. No re-indexing on restart. |

#### 3. Retrieval-Augmented Generation (RAG)

| Sub-component | Rust Crate | Role |
|--------------|-----------|------|
| **Retriever** | Custom bit Hamming KNN | Fetch the most relevant chunks for a user query. |
| **Context Builder** | Rust string formatting | Assemble retrieved chunks into a context window for the LLM. |
| **Local LLM** | `std::process::Command` → Ollama | Generate a fluent answer grounded in the context. Same approach regardless of language. |

#### 4. Desktop Frontend

| Layer | Technology | Why |
|-------|-----------|-----|
| **Framework** | **Tauri** | Tiny binaries (~5MB), native feel, Rust backend in-process. |
| **UI** | HTML + CSS + JavaScript (Svelte or vanilla) | Web technologies are familiar, allow rich UI. |
| **Backend** | Rust — all ML pipeline in-process | No Python, no sidecar, no IPC. Single binary. |
| **Packaging** | Tauri bundler | Produce `.exe`, `.dmg`, `.AppImage` installers. |

#### 5. Model Manager

A critical UX component for non-tech users:

```
┌─────────────────────────────────────────────┐
│  🧠 Model Setup                             │
│                                             │
│  zoloRAG needs a local AI model to run.    │
│  The recommended model (Llama 3 8B) is      │
│  ~4.7 GB and runs well on most laptops.     │
│                                             │
│  [📥 Download & Install (Recommended)]      │
│  [⚙️ I already have Ollama set up]           │
│  [❓ What model should I choose?]             │
└─────────────────────────────────────────────┘
```

- Bundles a **lightweight model manager** that wraps Ollama installation.
- On first launch: guides user to download Ollama + a model.
- Progress bars, estimated time, pause/resume.
- Allows switching models later (Settings → Model).

## Tech Stack Decision: Rust-Only from Day One

**Not "Phase 1 Python, Phase 2 Rust." That is how Phase 1 becomes permanent.**

### Why Not Python Sidecar

**1. PyInstaller is a liability.**
Works on your machine, breaks on end-user machines. Windows 10 vs 11, macOS Sonoma vs Sequoia, Ubuntu 22 vs 24 — each a new failure mode. Windows Defender flags bundled Python binaries as malware. macOS notarization rejects Python bundles. You will spend more time fixing builds than writing features.

**2. Cold start kills desktop UX.**
Python import (torch + sentence-transformers): ~1.5s. Model load: ~1.0s. Total per query: ~3s. User stares at a spinner, thinks the app is broken, uninstalls. Rust-native: ~50ms startup, ~500ms per query. Feels instant.

**3. The Torch tax is indefensible.**
sentence-transformers depends on PyTorch (~800MB bundled). You need a 384-dim embedding model and bitwise math. Candle loads the same ONNX models with zero PyTorch overhead.

**4. Two runtimes = double the pain.**
Python + Rust + JS to maintain. Three dependency trees. Two build systems. Every bug lives across an IPC boundary. As an OSS maintainer working alone, this is how projects die.

**5. Your target users deserve better.**
Non-tech Windows users don't have Python. You bundle 50MB of runtime they never asked for. Then the app feels sluggish. Then an OS update breaks the PyInstaller bundle. They won't come back.

### Rust-Only Is Ready Now

| Need | Rust Crate | Notes |
|------|-----------|-------|
| Text embeddings | `fastembed` or `candle` | Wraps the same ONNX models as sentence-transformers. Production-ready. |
| PDF text extraction | `pdf-extract` or `lopdf` | Handles real-world text PDFs. For scanned PDFs, shell to Tesseract. |
| KNN search | Custom (50 lines) | Hamming distance over bit arrays. Add SIMD for free speed. |
| Persistence | `serde` + `bincode` | Save/load index. Type-safe. Blazing fast. |
| Local LLM | Call Ollama via `std::process::Command` | Same approach regardless of language. |

### The Numbers

| Metric | Python Sidecar | Rust-Only |
|--------|---------------|-----------|
| Installer size | ~50MB | ~6MB |
| Startup time | ~2s | ~50ms |
| Query latency | ~3s | ~500ms |
| Runtimes to ship | 2 (Python + Rust) | 1 (Rust) |
| Build systems | 2 (PyInstaller + Tauri) | 1 (Tauri) |
| CI complexity | 3 OS × 2 runtimes | 3 OS × 1 runtime |
| OS update risk | High (PyInstaller breaks) | Low (native binary) |

### Addressing the Counterarguments

**"4–12 weeks to rewrite AskBit in Rust"**
No. The core pipeline is ~120 lines of Rust. Not a framework migration.

| Component | Lines of Rust |
|-----------|--------------|
| Load PDF, extract text (`pdf-extract`) | 3 |
| Chunk text by paragraphs | 50 |
| Embed chunks (`fastembed`) | 5 |
| Binarize to bits | 3 |
| KNN search (Hamming distance) | 40 |
| Build prompt, call Ollama | 20 |
| **Total** | **~121** |

Long weekend if you know Rust. 2–3 weeks learning from scratch.

**"Speed to MVP matters more than architectural purity"**
False dichotomy. Rust reaches MVP *faster* because there is no build hell:

| Approach | Working Prototype | Production Binary |
|----------|-----------------|-------------------|
| Python sidecar | 1–2 weeks | 6+ months (fighting PyInstaller, AV, notarization, cold start) |
| Rust-only | 3 weeks | 3 weeks (one `cargo build --release`) |

**"Many local RAG apps ship with Python sidecar"**
Name three that non-tech users love. GPT4All → C++. LM Studio → C++. Ollama → Go. llama.cpp → C++. whisper.cpp → C++. The market voted. Python sidecar is a niche pattern that dies in maintenance.

**"PyInstaller problems are manageable with good practices"**
Cope. PyInstaller is a reverse-engineering tool, not a build system. Every CPython release, every OS update, every dependency bump can break it. You cannot practice your way around Windows Defender or Apple notarization.

**"Phase 1 Python, Phase 2 Rust — gradual migration"**
This is how projects die. Users demand features, not rewrites. The Python version "works fine." The rewrite gets harder as the codebase grows. You end up on Python forever.

**"You already have AskBit's Python code"**
The code is not the asset. The *architecture* is (bit vectors → Hamming KNN → Ollama RAG). That architecture ports to Rust in 120 lines. The Python code is a prototype you leave behind.

**"You're comfortable with Python, not Rust"**
This is the only real argument. But ~120 lines of logic, the Rust Book takes a weekend, and `fastembed`/`pdf-extract` have working examples. Learning curve is 2–3 weeks, not months.

### Implementation Match with AskBit

| Component | AskBit (Python) | Rust Equivalent | Match? |
|-----------|----------------|-----------------|--------|
| Binarization `(vec > 0).astype(int)` | NumPy | `vec.iter().map(\|f\| *f > 0.0)` | ✅ Bit-exact. Same float input → same bit output. |
| Hamming distance | sklearn `metric="hamming"` | `popcount(a ^ b)` on bit slices | ✅ Bit-exact. Same algorithm, same result. |
| KNN search | sklearn `KNeighborsClassifier` | 40 lines of `min_by` over distances | ✅ Same ranking. |
| Ollama call | `pexpect.spawnu("ollama run ...")` | `std::process::Command` | ✅ Identical. Both shell to the same Ollama binary. |

The only difference: Rust uses ONNX Runtime (via `fastembed`) while Python uses PyTorch. Float outputs can differ by ~±0.0001, but:
- The bit vector approach is robust to ~5% bit noise.
- Relative Hamming distance rankings stay stable.
- Top-K matches are functionally identical.
- You can validate this in one afternoon: 100 sentences, 10 queries, compare top-K.

### First-Run Model Setup

The app does **not** bundle an LLM (4–8 GB would make the installer too large). Instead:

1. **On first launch**, the app detects if Ollama is installed.
2. If not, it downloads and installs Ollama silently (Ollama has cross-platform installers).
3. Then it pulls the recommended model (`llama3.2:3b` for lightweight, or `llama3.1:8b` for quality) with a progress bar.
4. **Total first-run time**: ~5–15 minutes depending on internet speed.
5. After that: **fully offline**.

### What Ships in the Installer

| Item | Size | Purpose |
|------|------|---------|
| App binary | **~6 MB** (single Rust binary) | The entire zoloRAG application — UI + ML pipeline + all logic |
| Embedding model (ONNX) | ~80 MB (downloaded on first run) | Embedding model for semantic search, loaded via `candle` |
| Ollama installer | ~200 KB (downloaded on first run) | Local LLM server |
| LLM model | ~2–8 GB (downloaded on first run) | The actual language model |

**No Python runtime. No PyTorch. No PyInstaller.** Single binary, zero runtime dependencies.

## Inspiration: AskBit

This architecture draws heavily from [AskBit](https://github.com/shanvit/askbit), a CLI-based FAQ RAG assistant that uses:

- **Bit vector encoding** of semantic embeddings for blazing-fast, memory-efficient retrieval.
- **Ollama** for local LLM-powered generative answers.
- **sklearn KNN with Hamming distance** for ultra-fast nearest-neighbor search.

zoloRAG takes AskBit's proven RAG pipeline, ports it to Rust (121 lines of core logic), wraps it in a **desktop GUI via Tauri**, swaps the FAQ JSON input for **PDF ingestion + chunking**, and adds an **install wizard and model manager** to make it accessible to non-technical users.
